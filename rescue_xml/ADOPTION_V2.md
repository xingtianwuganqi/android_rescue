# Android 领养申请 V2（1.3.0 / versionCode 21）

按 2026-10-02 最新更新的 `front_demand_v2.md`、后端 `API_v2.md` 开发，基线为 `rescue_xml`。保留原四 Tab、发布、图文详情、图片预览、点赞、收藏、评论及 Taku 广告；详情横幅继续位于文字和图片之间。

## 更新后的联系规则

新版获取按钮仍走登录、资料检查、分享资料确认、提交申请，不回退旧 GetContact，也不调用 checkPhone/bindPhone/短信验证。

联系方式来自当前登录用户的申请响应 `topic.getedcontact/contact_info`。GET 列表或申请详情后直接显示；不再提供或调用独立 V2 contact 接口，不发送 confirm_safety，不显示重新授权按钮。复制提供固定安全提示，再 GET 本申请详情，更新页面并复制当前联系；提示没有独立后端确认请求。

获取事实与申请状态分别处理：

- 未同意且无获取记录：没有联系方式。
- 申请中已有历史获取记录：仍显示已有联系，不自动变成沟通中。
- 同意沟通：后端同事务写入原 GetedContact，随后本人申请响应显示联系。
- 单份申请结束：保留获取记录，帖子仍可用时继续显示联系。
- 原帖联系方式修改：GET 获取当前值，无需重新同意。
- 整帖完成/关闭/删除、账号失效：后端响应联系为空；客户端同时检查帖子完成、删除和不可用状态，不显示或复制。

旧客户端继续原 GetContact、原黑名单/手机号校验及原帖子字段行为，旧获取不生成申请或沟通状态。本轮没有修改后端或关闭旧获取，不宣称所有客户端都必须获同意才可联系。完成/重开/删除仍由后端维持申请一致性。

## 页面与入口

- **我的 → 领养资料**：本人年龄、城市/区县、住房、工作及经验。独立区县选择不改首页城市、不申请定位；创建不传 version，更新带资料 version。保存不自动申请。
- **消息 → 我的申请**：新增 `AdoptionMyApplicationsActivity` 和独立 ViewModel，GET `adoption-applications/mine`。复用列表 XML/Adapter，默认全部，可筛选申请中、沟通中、已结束，刷新和分页每次保持筛选。显示原帖、状态、申请时资料、当前联系，以及详情/放弃/复制操作。
- **消息 → 收到的申请**，或**本人原帖 → 管理申请**：GET `adoptions/mine/applications`，可传 topic_id，三个状态筛选。与我的申请使用独立角色和接口；收到列表不显示申请人联系方式。
- **原帖联系按钮**：从 application-state 决定角色及按钮状态；未登录成功只恢复一次。资料不完整先填写，完整资料复用，仍需本次分享确认。沟通中 GET 本申请详情显示 topic 联系；申请中/已结束也可打开详情查看历史获取联系。
- **申请详情面板**：重新查询服务端管理权限。送养人确认同意、结束申请或选择沟通中的实际接宠人完成送养；申请人查看本人资料快照、联系及放弃申请。
- **原帖更多菜单**：管理/选择接宠人、关闭、旧帖兼容重开、删除。重开仅允许无申请历史的旧完成帖；有历史或已关闭需重新发布。无候选人可关闭，不伪造成功申请。
- **消息页顺序**：系统消息、我的申请、收到的申请、点赞、收藏、评论。两类申请各有独立分类角标，旧点赞/收藏/评论仍映射 messageType=1/2/3。保留四 Tab，消息 Tab 角标为旧四类未读加申请总未读一次；没有独立申请通知入口。

个人页只保留“领养资料”，仅在登录 userId 与目标 userId 一致时出现；两个申请入口移至消息页。他人页不因登录事件切换成自己的页面。完成使用 workflow_version，申请动作使用申请 version，资料使用 profile_version；其他有效申请的结束由后端统一事务处理。

## 列表顶部提醒、分页与角标

两个申请列表顶部各自查询 `adoption-notifications?role=mine/received&unread=true`；原帖管理入口同时限定 topic_id。提醒不随 applying/communicating/ended 筛选改变，只按身份、帖子和未读过滤。每项展示正文及设备本地时间格式化的 created_at。

点击提醒只 POST 该条 id/read。成功展示正文、移除这一条，更新对应分类及全局消息角标，并重新获取服务端统计；失败保留提醒/计数，可重试。连点禁用提交。进入列表、刷新、查看申请详情不写 Notification.read；后端旧 application.read_at 不用作通知角标依据。旧 AdoptionNotificationsActivity 只为已有内部 Intent 做鉴权转发，不再作为独立通知入口。

提醒与申请各自分页、has_more、loading 和错误状态；按 id 合并防重复。初次条目加载转圈，成功空页显示“暂无数据 / 请点击重试”，空区域可重试；失败显示具体错误和点击重试。提醒存在时仍保留顶部区域，条目空状态不遮住提醒。追加失败保留已加载页，点击错误重试失败的原页，底部加载更多仅在非空列表显示。

通知 DTO 增加 kind/role，列表及统计 DTO 的分类数使用可空字段，不把字段缺失当 0。新后端直接使用全范围 mine_unread_count/received_unread_count，当前页无提醒不清零。缺分类数或 role 时，分页读取当前账号全部未读通知和全部本人申请历史（不限定状态），按 application_id 归属归类，再应用 role/topic_id；不能用 kind/target 判断。归类未完成不猜测分类数，新接口正常时不额外全量拉历史。

单帖统计仅更新该页，不能覆盖消息页全局数。失败保留上次成功计数，切号/退出取消分页和已读任务、清列表和角标。MainActivity 与 MessageFragment 共享 MessageViewModel，前台/返回及已读成功后更新统计，申请总数与分类数不重复累加。

本轮实现应用内消息 Tab badge。桌面数字角标取决于系统通知渠道、通知许可和启动器支持；工程当前没有完整业务离线推送渠道，本轮不新增推送渠道，不承诺所有启动器显示同一桌面数字。站内提醒不依赖系统通知许可。

## 隐私与生命周期

V2 使用独立 OkHttp/Retrofit suspend Response、JSON/Bearer，不复用旧 awaitResp、不记录请求或响应正文。400 字段错误、401 登录失效、403 无权限、404 不可用、409 版本/资料冲突分别处理；只有 401 退出登录。旧 awaitResp 去掉整段 body 日志，避免原帖接口返回已获取联系后写日志；其他旧网络行为保持原样。

每次请求捕获用户/token/会话版本，账号变化后丢弃旧响应；协程取消实际 HTTP Call。切号/退出清空新页面资料、联系、消息及待操作。私人输入和列表不保存 View 状态；联系方式不进 Intent、result_model、SharedPreferences、SavedStateHandle 或通知。本人申请列表/面板返回后台时清理联系数据，回前台重新加载。

申请幂等键覆盖账号、帖子、资料版本和说明的摘要。同次未知结果先查状态，同内容重试复用键，明确重新申请/编辑内容使用新键；忙碌时拒绝重复提交。保存资料后仍重新查询、重新确认，不自动提交申请。

新 DTO 的 topic.preview_img 是字符串，申请人使用 user_id/nickname/avatar；不复用 Parcelable 旧帖子/登录用户来承载私人申请数据。原详情返回列表的公开模型清除联系字段，不转存 V2 联系。

## 服务与安装包

当前 Debug 与 Release 默认均使用测试环境 `http://test.rxswift.cn/`，登录、发布、帖子和 V2 申请/消息接口使用同一环境。可通过 `-PAPI_BASE_URL=https://your-service.example/` 同时覆盖两套接口；`-PADOPTION_BASE_URL=...` 仍支持单独覆盖 V2 地址。切换环境后需使用测试环境账号重新登录。

切换测试环境后，只读检查 `http://test.rxswift.cn/api/v2/adoption-profile/me` 返回 HTTP 401，接口可达且要求认证；尚未使用测试账号进行完整业务联调。没有执行数据库迁移、灰度开启、真实申请或发送真实通知。部署时使用更新后的联系联通契约，不能混用上一版独立 contact API。灰度/回滚不关闭旧获取，原完成/重开/删除继续维持申请一致性。

安装包：`app/build/outputs/apk/debug/app-debug.apk`、`app/build/outputs/apk/release/app-release.apk`，release 沿用原工程签名。

## 部署后的验收重点

1. 原四 Tab、发布/图片、推荐/同城/搜索、图文中间横幅、收藏/评论回归。
2. 未登录只恢复一次；资料保存后需确认，取消不申请；区县不改首页城市，编辑资料不改旧快照。
3. O 送养、A/B/C 申请；无旧获取时申请中无联系，同意后沟通中有联系。新版不调用验证码或旧联系接口；旧客户端按原手机号校验仍能获取且不新增申请。
4. 有旧获取记录的申请中仍有联系；结束 A 不影响 B/C，A 获取记录继续可用。O 修改联系后刷新显示新值，无重新同意步骤。
5. 完成 B 后 B completed、其他有效申请 not_completed，所有本人申请联系为空；关闭/删除同样隐藏。历史快照不可用时显示占位。
6. 本人/他人入口、全部/三个状态分页、版本冲突、超时/连点/旋转/切号/后台清理、复制刷新当前值及无旧联系回退。
7. 站内通知已读/未读、两类 target 导航、已删除/失权目标占位；有无系统通知权限均可操作。
