# 申请列表 UI 重构（2026-10-19）

参考用户提供的 IMG_1916.PNG（我的申请）与 IMG_1917.PNG（收到的申请）。范围为 rescue_xml 的两类申请列表，不修改用户需求文档或 Compose 工程。

## 实现

- 共用顶部固定四段筛选：全部、申请中、沟通中、已结束。橙色选中项、浅灰圆角底与分隔线；两个角色默认均为全部，恢复已有筛选时保持原选择。全部请求不传 status，避免空枚举参数。
- 列表浅灰背景，白色描边圆角卡片，使用 dp/sp、独立 XML/ViewBinding 和复用 ViewHolder；替换原照片/文本/按钮的纵向堆叠。
- 我的申请：顶部状态标签与时间；缩略图、帖子摘要及箭头组成原帖入口；底部固定联系区，未获取时显示“暂无已获取的联系方式”。隐藏本人头像及重复资料块。有效联系仍由原 AdoptionContact 判断，单份申请结束不擅自撤销历史获取。
- 收到的申请：头像、昵称、时间及右侧状态标签；终态结果、申请时资料块、分隔线及原帖卡片。完成结果标示“送养人报告”。点击资料块继续打开原资料快照面板；不展示申请人电话或代入申请人身份查询。
- 沟通、拒绝、结束、完成、放弃及复制仍调用原 action flow/contact copy，保持刷新状态、确认、版本与幂等校验。操作按钮右对齐，窄屏/大字体自动换行，忙碌时禁用。
- 不可用/删除帖子清除图片与导航，清除失效资料；复用卡片时重置角色、联系、状态、图片和操作。缺预览图继续使用原去重补取。
- 下拉刷新代替固定刷新按钮，保留非空列表加载更多与各自的提醒分页、失败重试、空页重试。去掉列表顶部重复资料说明；提醒为空仍隐藏整个提醒区域。
- 仅申请列表使用新容器，资料填写与其他领养页面保留原容器及滚动布局。
